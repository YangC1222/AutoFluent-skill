# 方案前澄清与确认

在制定或调整整套工作流程前，先检查哪些信息已经明确，哪些缺口会改变方案。对影响方案的未知项及时向用户提问，与用户确定合适的做法。不要用未经确认的假设代替用户对关键问题的选择。

## 判断哪些事项需要询问

先读当前请求、已有对话、项目约定和相关文件。能够通过只读检查获得的信息先检查；用户已经明确或授权的事项不重复询问。检查文件或现有设置能确认“当前是什么”，不一定能确认“用户希望是什么”。区分这两者。

按任务需要检查整条流程，重点关注：

- 目标和验收：希望回答什么问题、需要哪些量、精度或比较基准是什么。
- 输入和物理：几何/尺寸/单位、材料、工况、边界条件、稳态或瞬态，以及会影响结果的模型假设。
- 网格和求解：结构化可行性、壁面分辨率、网格规模、求解策略、收敛标准、资源或时间限制。
- 验证和交付：守恒、网格无关性、理论比较的定义、输出文件与必要图表。

这些是检查维度，不是每次都要发给用户的问卷。只问当前缺失、不能可靠推断、且会改变结果含义、方案、成本或交付范围的问题。例如缺少热边界类型时，不能自行把恒热流当成恒壁温；已有明确速度列表时，不要再次确认速度。

## 及时提问并共同选择

1. 发现关键缺口就提问，不要等计算完才补问。每轮聚焦 1–3 个相关问题，简要说明为什么答案会影响方案。
2. 能比较选项时给出 2–3 个选项，说明实际差异，并给出有依据的建议；允许用户提供其他方案。缺少事实参数时直接询问，不编造默认值。
3. 有异步提问工具时用于文本澄清；需要文件时直接在对话中请求。等待期间继续不依赖答案的只读检查或准备工作。
4. 对决定物理模型、工况、重大算力投入或交付范围的必要答案，保持问题待答，不启动依赖该答案的操作。不把沉默或等待超时视为确认。
5. 用户回答后，用简短文字整理目标、已选方案、关键参数、验证方式和输出，明确剩余待定项。已有回答足以确定方案时直接继续；只有仍有实质分歧或新增关键选择时才再次确认。不要添加机械的“批准执行”环节。

## 执行中发现新问题

执行过程中若发现新信息使方案需要实质改变，例如结构化网格方案不可用、原定物理假设不成立或资源需求明显增加，及时说明证据、影响和替代选项，再询问尚未授权的关键选择。已有明确授权的替代路线按约定执行并说明理由。

保持已确认条件在当前任务记录中可追溯，优先使用用户最新回答。常规文件命名、代码整理和不影响结果的实现细节自行处理；不要把这个 skill 扩展成所有操作都要询问。对已有网格的后处理任务，不因本检查流程擅自增加重划网格或重新计算。
